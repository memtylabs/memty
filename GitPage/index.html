The problem

Every chat starts from zero.

You explain your project, your stack, and your preferences again and again. When an assistant does remember, that memory is locked inside one company's product, mixed with everything else, and hard to inspect.

PROBLEM 01

You repeat yourself

Each new chat, tool, or model needs the same background again. That costs time and tokens, and things get missed.

PROBLEM 02

Memory is locked in

What ChatGPT knows about you doesn't help in Claude, Gemini, or your code editor. Switching tools means starting over.

PROBLEM 03

You can't see or control it

Built-in memories are opaque. It's hard to tell what was stored, fix what's wrong, keep secrets out, or delete something for good.

What Memty does instead

One vault, every AI

A single local file that works with chat websites, MCP clients, the clipboard, and Python.

Small, clear facts

Memory is stored as short Title: value facts, not long transcripts, so it stays accurate and cheap to send.

You approve everything

Facts from chats are only proposals. You edit or untick them before anything is saved.

Private by default

Nothing leaves your computer until you press Send. Private facts appear to AIs only as [private].

How it works

Save once. Recall anywhere.

Everything runs on your machine. Every assistant reaches the same vault through one local daemon: browser chats through a small local bridge, desktop and coding agents through the Model Context Protocol, and you through the terminal. Nothing is synced between apps. They all read the same file.

A fact's journey: from ChatGPT to Cursor

  1. 01Select

    In ChatGPT you select "We deploy on Fly.io" and click ＋ Save to Memty.

  2. 02Propose

    The bridge turns the selection into short facts on your computer, with no model call. You review and save.

  3. 03Store

    memtyd writes deploy_target: Fly.io into the project.api namespace as a confirmed fact.

  4. 04Recall

    In Cursor the agent calls memty_sync for project.api. memtyd builds a 120-token capsule and runs the privacy gate.

  5. 05Receipt

    Cursor gets Deploy target: Fly.io. A receipt records that one fact was served, without its value.

Five ideas behind it

  1. 01Atomic facts

    One value per namespace.slot, at most 40 tokens. Saving a new value replaces the old one and keeps the history.

  2. 02Namespaces

    Separate contexts such as work.project or personal. A chat only gets the namespace you choose.

  3. 03The compiler

    Builds a small capsule per request: newest facts first, or the most relevant ones for a question, under a hard token budget.

  4. 04Privacy gate

    Every capsule is checked: private values are masked, secrets stop the request, blocked providers get nothing.

  5. 05You decide

    Proposals need your approval, from chats and from agents. Your own facts can't be overwritten automatically. Deleted means deleted.

Get started

Three commands. One time.

Requires Python 3.10 or newer on Windows, macOS, or Linux. No account, API key, or sign-up.

Install Memty

Terminal
pip install memty

Installs the CLI, the vault, the MCP server, and the browser extension files.

Start the bridge

Terminal
memty serve --autostart

Starts Memty now and every time you log in. Per-user, no admin rights. Undo with memty serve --no-autostart.

Add the extension

Terminal
memty extension --open

Open chrome://extensions, turn on Developer mode, click Load unpacked, and pick the folder that opened. It pairs itself, with no token to copy.

Prefer the terminal? memty remember work.project editor "VS Code" saves a fact, and memty clip work.project copies your facts for any AI app.

Plain lines, no tags

  • One Title: value line per fact. Facts with the same title share a line.
  • Newest facts first, so something you saved a minute ago is always included.
  • If the list is too long, the oldest lines are left out to stay within budget.
  • Private values show as [private]. A secret fact stops the request instead.
  • If the block is already in your message, Memty won't add it twice.

How facts are picked from your selection

  1. 01Clean

    Removes formatting, links, citation numbers like [1], and Memty blocks you pasted earlier.

  2. 02Find candidates

    Bullet points and Key: value lines first, otherwise the first five plain sentences of 4 to 30 words.

  3. 03Filter

    Drops questions, headings, fragments under 3 words, and lines that look like code.

  4. 04Shape

    Uses the key as the title (or the first meaningful words), groups file paths, caps each fact at 40 tokens, max 12.

  5. 05Summarize code

    Code is never stored. Each block becomes one line, such as Python code in db.py defines connect, Ledger.

No AI model is used by default. Extraction runs on fixed rules, so it's instant, free, private, and predictable. It reads the shape of text (bullets, Key: value lines, short sentences), not its meaning, which is why every proposal goes through your review. For smarter extraction, set MEMTY_OLLAMA_MODEL (for example llama3.1) to use a local Ollama model. It still runs on your machine, and Memty falls back to the rules if Ollama doesn't answer.

Trust control plane

No black box. No silent overwrites.

Memory you can't inspect is memory you can't trust. Memty fills itself without a model, lets agents suggest instead of overwrite, and keeps a receipt every time it hands memory to an assistant.

MEMTY SCAN · MEMTY INIT

Starts full, not empty

Reads pyproject.toml, package.json, Cargo.toml, Dockerfile, and .env.example and saves your stack as facts in milliseconds, with no model and no network. From env templates it keeps key names only; a real .env is never opened. Facts you confirmed or deleted are never touched.

MEMTY INBOX

Agents propose, you decide

When Cursor or Claude Code learns something, a brand-new fact is saved as unconfirmed. A change to a fact you already have waits in your inbox: memty approve or memty reject. Approving never lowers a fact's privacy level.

MEMTY REPORT

A receipt for every capsule

Recall, clip, MCP, and the browser each log what they served: which client, how many facts and tokens, how many values were masked, and any request a secret blocked. Slot names only, never values.

Inbox · example
$ memty inbox
[1] project.api -> cache_engine: "Redis" [confirmed] => "DragonflyDB" (Proposed by Cursor)
      why: compose.yaml runs dragonfly

$ memty approve 1
[1] approved: project.api.cache_engine = "DragonflyDB" (user-confirmed, v2)

The old value stays in memty history. memty reject 1 leaves the fact untouched.

Privacy & security

Built so websites can't read your vault.

Every fact has a privacy level. Every request is checked against it before anything is shown to an AI.

Only for local models and providers you trust. Cloud chats don't receive it.

(left out)

Cloud assistants see a placeholder. The real value stays on your computer.

Client: [private]

SECRET

Never sent to a cloud assistant. A matching request is stopped and asks for a local model.

request refused

How the local bridge is protected

  • Listens only on 127.0.0.1, never on your network. This can't be changed.
  • Every data request needs a secret token, stored owner-only beside your vault.
  • Web pages are refused. Only browser extensions may connect, and only those you approved.
  • Pairing is trust on first use. To add a browser or a reinstalled extension, run memty pair: one more extension may connect within two minutes.
  • Host checks block DNS-rebinding attacks. Writes must be JSON, which blocks form-based attacks.
  • Only the extension's background worker holds the token. Scripts inside chat pages never see it.
  • The site is identified from the tab's real address (ChatGPT → openai), so a page can't pretend to be trusted.
  • A browser can't claim to be a local model to get SECRET facts, and can't make a SECRET fact public. Only your terminal can.

What to know

  • When you press Send, the facts in your message go to that AI company, like anything else you type. Review the block first.
  • The vault file is not encrypted. It's protected by your computer account. Don't put it in a synced folder such as OneDrive or Dropbox unless you want it uploaded.
  • To revoke access, run memty serve --new-token and restart the bridge. Every extension must pair again.
  • To erase everything, delete the ~/.memty folder.

Don't trust us. Attack it.

61 adversarial tests

tests/test_memty_security.py tries to break every promise on this page. A failing test means a vulnerability.

  • Privacy gate: SECRET facts never reach any cloud provider, for any question, including look-alike "local" names and Unicode tricks.
  • Credentials: API keys, tokens, private keys and password: … lines are always stored as SECRET, however they're saved.
  • Forget: a forgotten value is gone from every table, the search index, and the raw bytes of the file on disk.
  • Browser bridge: DNS rebinding, web-page origins, forged tokens, a second extension pairing, malformed requests.
  • Daemon and MCP: wrong tokens, internal methods, agents trying to overwrite or downgrade your facts.
  • Injection: SQL, search syntax, and stored text that tries to forge Memty's context markers.

Under the hood

Simple rules, strictly enforced.

Memty's behaviour is set by a handful of guarantees, each covered by automated tests.

GuaranteeHow it's enforced
No contradictionsOne value per namespace.slot. A new value supersedes the old one, which moves to an audit table with its version number.
Facts stay smallValues over 40 tokens are rejected, so each fact is one clear statement.
Deleting is permanentForgetting a fact tombstones it and purges its value and history. Deleted pages are zeroed, the search index is compacted, and the write-ahead log is checkpointed, so the value can't be recovered from the file.
Keys are never sharedValues that look like credentials (API keys, tokens, private keys, password: …) are stored as SECRET, whatever level was asked for.
Saved text stays dataA stored value can't close or forge the capsule's own markers, so text saved from one chat can't inject instructions into the next.
Automation can't overrule youAutomatically extracted facts can't overwrite facts you confirmed, and can't restore facts you deleted.
Agents ask firstAn agent's change to an existing fact goes to the inbox, never straight into the vault. Approving keeps the fact's privacy level and provider rules.
One writerAll tools go through one memtyd per vault, which handles one request at a time, so concurrent tools can't corrupt or overwrite each other.
Every capsule is accounted forEach capsule served, and each request a secret blocked, writes a receipt with counts and slot names. Values are never written to receipts.
Bounded contextEvery capsule is checked against a hard token limit: 350 for chat websites, 200 for the clipboard by default, 120 for MCP, and 600 for the API by default.
Newest firstWithout a question, the most recently saved facts lead. With a question, facts are ranked by keyword overlap and optional semantic similarity.
Raw text stays outSource text archived with a fact is never put in a capsule. It's only returned by an explicit drill-down call.
Rules per namespaceLogical rules such as "when writing database queries, always use async Motor" are stored per namespace and managed with memty rule.
FastBuilding a capsule takes about 3 ms (median) with 300 facts. Search uses SQLite FTS5 when available, with a plain SQL fallback.
Few dependenciesThe vault and compiler use only the Python standard library. The package adds the official MCP library.

FAQ

Good questions.

Is my data stored in the cloud?

No. Your facts live in one file on your computer, ~/.memty/ledger.sqlite3. Memty has no servers, accounts, sync, or telemetry, and the browser only keeps settings, never facts.

The one moment facts leave your computer is when you press Send in a chat: the block in your message goes to that AI company, like anything you type.

Does Memty really use fewer tokens?

In our published benchmark, yes: across three live runs passing one architecture handoff between Claude and Gemini, Memty's selected context used 5,448 input tokens versus 13,989 for replaying the full documents (61% less) and 9,386 for retrieved snippets (42% less), and it returned all 30 expected values exactly.

That's one synthetic task, not a guarantee for every workload, and it doesn't count the effort of creating the facts. The prompts, raw results, and code are public so you can rerun it. See Proof.

How do the browser and my coding agents share memory?

They all talk to the same local daemon, memtyd, which owns your vault file. The browser extension reaches it through the bridge on 127.0.0.1:8765; Cursor, Claude Code, Codex, and other MCP clients reach it through their own MCP server; the CLI reaches it directly. Nothing is copied between apps, so a fact saved in ChatGPT is in Cursor's next recall.

Can my coding agent change my facts?

Not on its own. An agent can add a brand-new fact, saved as unconfirmed. Any change to a fact you already have waits in memty inbox until you run memty approve. Facts you confirmed or deleted can't be changed by automation.

Does Memty use AI to pick facts from my chats?

Not by default. It uses fixed rules: it reads bullets, Key: value lines, and short sentences, and skips questions, headings, and code. That makes it instant, free, and private. Because rules don't understand meaning, every proposal goes to you for review first.

Set MEMTY_OLLAMA_MODEL to use a local Ollama model instead. It still never leaves your machine.

Why didn't my newest fact show up?

Since 0.2.0, facts are listed newest first, so a fact you just saved always leads. Check that it was saved to the namespace you're using (shown in the save message and on the facts page).

What does "This browser isn't connected to Memty yet" mean?

For your safety, Memty only talks to extensions you approved. A reinstalled extension or a second browser counts as new. Run memty pair in a terminal, then click Try again.

If memty pair says Cannot pair, another Memty bridge, for a different vault or an older version, is using port 8765. Stop it, then pair again.

Which browsers and sites are supported?

Chrome, Edge, and Brave, on ChatGPT (chatgpt.com and chat.openai.com), Claude.ai, Gemini, and Perplexity. Chat sites change often, so if the pill can't find an answer, select the text you want instead.

Does it work offline?

Yes. Saving, editing, and building capsules all run locally. You only need the internet for the AI chat itself.

What happens when I delete a fact?

Its value and whole history are removed from the vault, and automatic saving can't bring it back. You can only restore it by adding it again yourself.

Can I keep secrets in Memty?

Mark them Private to have chat AIs see only [private], or SECRET so any request that would include them is refused. The vault file itself isn't encrypted, so it relies on your computer account's protection.

Is the web workspace connected to the vault?

Not yet. The Memty web app is a separate companion; its account conversations and MongoDB memory don't sync with the local SQLite vault.

How do I update or uninstall?

Update: pip install -U memty, then memtyd stop so the daemon restarts on the new version, then memty extension and click reload on the extension. Open chat tabs update by themselves. Restart your MCP clients to pick up new agent tools.

Uninstall: memty serve --no-autostart, pip uninstall memty, and remove the extension. Your vault stays in ~/.memty until you delete it.
